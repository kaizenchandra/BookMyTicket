# ADR 067: Private onboarding save recovery

FE:PRV-02/03/06 and BE:PRV-02/03 require resumable private onboarding corrections. PUT /api/v1/organizations/:id/onboarding retains its existing validated details and expectedVersion request. Organization/input version identifies the save; original actor and complete normalized input are bound to it.

Migration 060 adds immutable providers.onboarding_saves. It retains actor, organization, input/output versions, original editable state and a SHA-256 fingerprint of a fixed-order array containing the operation domain, organization, actor, version and all five normalized fields. Object property order does not affect matching. It stores no second copy of business/contact fields or response JSON. The hash is a matching mechanism, not encryption or anonymization; existing access and retention controls still apply.

The adapter locks the organization then current owner membership. Identical original-actor replay reconstructs the original response from saved metadata and the validated matching request details. Changed fields or actor return ONBOARDING_SAVE_CONFLICT. Replay runs before current editable-state validation, audits provider.onboarding.save_recovered without contact content and never writes current details/version. If audit persistence fails, the response is withheld.

New saves require editable state and matching version. Private details, organization version, durable fingerprint record and provider.onboarding.saved audit commit together. Audit failure rolls all changes back. The organization lock serializes saves, name edits, submission and review; there is no external network call inside this transaction. Current ownership is required on every retry; authentication remains at the HTTP boundary.

The frontend retains the original request after failure and offers retry/dismissal. Successful recovery fetches current private details and preserves different entered data rather than applying the historical result. Pending recovery blocks new saves and reports dirty state to the parent submission control. Reload remains explicit and confirms discarding unsaved entries. Session/organization/reviewer-mode changes clear loaded private data and recovery; stale load/save responses are ignored. Attempts are memory-only and navigation warns about unresolved work.

Tests cover concurrent normalization/property-order replay, one saved event/result, per-replay audits, no raw contact values in command/audit records, all field conflicts, actor conflicts, audit rollback/withholding, later edits/approval, revoked ownership and immutability. Pre-migration saves are not reconstructed and the prior next-version shortcut is removed. Browser/session/form/accessibility acceptance, approved retention and reload persistence remain open.
