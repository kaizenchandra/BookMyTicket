# ADR 043: Explicit venue contact publication

FE:VEN-01 requires contact information where permitted. Venues owns separate phone/email values, an explicit public-display flag and contact version. Migration 043 defaults existing records to empty values and private display; account/provider identity contacts are never copied. Provider authorization is an operational publication permission, not proof of ownership or verification of the supplied phone/email.

POST /api/v1/organizations/:id/venues/:venueId/contact accepts expectedVersion, phone, email and public. Phone is empty or an international + prefix followed by 7–15 digits (nonzero first digit); email is empty or valid bounded email syntax. Public display requires at least one contact. The provider UI explicitly asks the editor to authorize public display. Only members with organization write access may save. The transaction locks the tenant-owned venue, rejects stale versions, increments contact_version and writes venue.contact_updated with organization/version/public metadata only. Failure to audit rolls back the mutation. A repeat using an old version returns 409; reload and compare an uncertain result before retrying.

The public adapter selects contact as null unless publication permission is enabled; private values are never returned to the public application layer. Existing provider approval and published-listing gates still apply to the venue. Disabling publication removes contacts on subsequent reads while retaining private values; clearing values with publication disabled deletes stored values. Already delivered pages cannot be recalled. Authorized organization members retain access through the protected workspace list.

The customer UI labels these as venue-supplied contacts, renders escaped text and bounded tel/mailto links, and shows a fallback when absent. No verification messages or calls are sent. Contact versions are independent of guidance versions. Contact changes do not alter accepted bookings or occurrence snapshots.

Integration evidence covers permission/tenant boundaries, strict validation, private response omission, publication, withdrawal, clearing, concurrent edits and audit rollback. Browser link handling, keyboard/accessibility acceptance and contact verification remain open. Media and independent venue publication are separate remaining requirements.
