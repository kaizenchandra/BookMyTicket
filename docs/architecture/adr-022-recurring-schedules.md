# ADR 022 — bounded atomic recurring scheduling

Inventory scheduling now accepts a daily/weekly series template through POST `/api/v1/occurrences/series/preview` and `/api/v1/occurrences/series`. The organizer uses the existing saved-plan scheduling form in `/partner/venues`. Both endpoints authenticate and require write membership, approved organization, owned published listing and an owned saved plan. Preview is read-only and returns dates/time zone; it explicitly does not reserve dates or claim conflict verification.

Domain rules: 2–24 candidate dates, interval 1–12 days/weeks, at most 366 days total, explicit excluded start dates from the candidate set, and at least one retained session. Civil dates shift while preserving the submitted explicit offset. Start/end/sales-close require numeric offsets. Publication checks every generated timestamp against the venue's IANA zone, rejecting DST-crossing mismatches rather than silently shifting local time. Split series at a DST boundary. Sales opening is one common instant; closing moves with the session.

One local unit of work creates all retained occurrences, plan/resource snapshots, audit, per-session commands and Catalog session projections. Existing schedule conflicts/turnaround and price validation apply to every session. Any failure rolls everything back. Series operation keys are actor-scoped, store a full-input fingerprint and the original occurrence IDs, and serialize through the existing actor advisory lock. Identical concurrent/lost-response retries return the original IDs; changed input conflicts. Permission/organization approval is rechecked before replay. Individual child keys are derived from the actor/series key/index and remain stable. Migration 027 stores series command outcomes; it does not add inventory counters.

The UI first obtains a server preview, then publishes the exact current form values. Editing any value invalidates preview. Controls are disabled during requests; failure preserves input. Successful creation refreshes the actual session list. Pricing policy and attendee forms remain explicit per-session configuration; creating a schedule never silently approves commercial terms.

Tests: six parallel identical requests, excluded dates, read-only preview, changed retry, permission revocation, later-session overlap rollback (occurrences/projections/commands), calendar rollover, count/span bounds and missing explicit offset. Existing seated/GA booking tests continue to cover the downstream workflow. Browser acceptance, load/latency and process-crash verification are not inferred from these tests.

Scope still partial for BE:EVT-02/03, BE:SCH-09 and FE:OPS-E-01: this creates bounded concrete series and creation-time exclusions. Editing a published recurrence rule, moving one already-created session, bulk policy/form assignment, postponement/cancellation remedies and multi-day pass entitlements remain outstanding. This is not an RFC 5545 RRULE engine.
