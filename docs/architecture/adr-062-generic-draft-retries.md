# ADR 062: Durable generic draft-edit replay

FE:CAT-01/08 and BE:CAT-07 require recoverable edits with concurrent-write protection. Generic PUT /api/v1/listings/:id previously conflicted after a successful save whose response was lost. Migration 055 adds immutable catalog.draft_edits keyed by listing/input version, storing actor, normalized input, resulting version, original result and timestamp.

The edit transaction locks the listing and checks current writable organization membership before inspecting either prior commands or category restrictions. The same actor and semantically equal JSON input receive the original result. JSONB equality makes metadata key ordering irrelevant; normal request validation trims core text before comparison. Changed payload or actor conflicts. Current membership downgrade/revocation blocks replay. Request versions are bounded to avoid integer overflow.

For new commands, the existing editable-state/version and category-editor restrictions remain. Revision, state/content update and durable result commit together. Historical replay never updates the listing, including after later edits, submission or publication. It returns historical content, so callers must refresh current status. Pre-migration edits are not backfilled. Category-specific keyed draft saves retain their existing behavior; generic create commands remain outside this replay mechanism.

The frontend captures the original edit URL/body. Retry original draft save resends that body rather than later form changes. On successful recovery it refreshes listing data, retains the form, advances that form's expected version only when it still edits the same listing, and keeps the parent unsaved-work indication. A returned historical version may still conflict with newer server state; the UI asks the user to inspect refreshed status. Dismiss draft retry clears only the local recovery attempt. Session changes clear attempts. Browser closure recovery and browser/form/accessibility acceptance remain unverified.

Tests cover six identical concurrent edits, one revision/result, normalized metadata key-order equivalence, changed title/metadata/actor conflicts, exact old replay after later edits and publication, current membership checks, immutability and noneditable-state protection. The older venue test now expects identical retries to succeed while retaining one revision and a changed-payload conflict check. Retention approval and generic creation retries remain open.
