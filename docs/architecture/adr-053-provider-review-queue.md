# ADR 053: Provider review queue pagination

FE:ADM-UI-05, FE:INT-09 and BE:API-05 require usable provider reviews and bounded, stable pagination. The aggregate review endpoint truncated providers at 100, making later applications unreachable in the admin UI. GET /api/v1/admin/providers now returns at most 20 submitted applications with an optional nextCursor; the admin page uses this endpoint for provider cards. The aggregate endpoint is retained for existing consumers and listing reviews; its legacy provider summary still caps at 100 and is not a complete queue API.

Ordering is organization creation time and UUID ascending. Both fields form an exclusive continuation boundary. Database timestamps are serialized with six fractional digits rather than round-tripped through JavaScript Date (which would lose microseconds). Both boundary query fields must be supplied together. Cursors are validated data, not access credentials; every page requires authentication, current moderation permission and existing MFA policy. Responses expose only the same organization metadata as the prior queue. Private business/contact data remains behind the existing audited onboarding API.

Optional kind filters accept cinema/event/sports or an empty all-types value for native HTML forms. Migration 050 adds partial submitted-state indexes for unfiltered and type-filtered ordering. The query fetches 21 rows to determine continuation, returning 20. This is a live queue, not a snapshot: reviewed applications disappear; a previously created application resubmitted behind the cursor requires returning to the first page. No submission-time FIFO or frozen total is claimed. Removing the cursor organization from submitted state does not invalidate continuation because no cursor-row lookup is required.

Native GET forms reset pagination on filter changes; navigation links preserve the filter and exact boundary in the URL. Browser Back/Forward can restore the requested URL. Loading/error/empty states and retries are explicit. Existing version checks continue protecting decisions against stale cards. Browser navigation, scroll restoration, keyboard/accessibility acceptance and load performance remain unverified. Listing queue pagination remains separate work.

Tests cover 105 equal-timestamp applications across six pages, ordering without duplicates, filtered/empty results, a boundary application leaving the queue, malformed and incomplete cursors, unauthenticated/non-moderator/revoked access, and server-rendered navigation links. Tests choose timestamps beyond earlier fixtures to support reruns without resetting the shared isolated test database.
