# ADR 049: Bounded inbox read-state actions

FE:ENG-04 and BE:NTF-11 require read/unread state. Notifications now returns an account-wide unreadCount with each list page, supports marking a notification unread, and atomically marks an explicit displayed selection read. Migration 047 adds a partial owner index for unread counts. Notification delivery and business events remain unchanged.

POST /api/v1/notifications/read accepts 1–20 distinct UUIDs, matching the maximum displayed page size. The adapter locks all matching owner rows in deterministic UUID order and checks that every requested ID exists before updating anything. A foreign/missing ID returns 404 and rolls back the entire operation. Selected records use coalesce(read_at, statement_timestamp()), preserving existing read timestamps on retries. The stable response contains sorted selected IDs and read=true. No timestamp-wide or global mark-all command is introduced; arrivals outside the explicit selection remain unread.

DELETE /api/v1/notifications/:id/read sets only the authenticated owner's matching row to unread; repeat requests are idempotent. Existing POST single-read behavior is preserved. Authentication/active-account checks apply to all requests, and unknown IDs reveal no other account's notification data. Concurrent opposite read/unread actions serialize on row locks; their final state follows database execution order.

The count is for the entire account, regardless of unread filter or page cursor. Page and count reads reflect current committed data at their respective queries, not a frozen cross-query snapshot; new deliveries can change the total immediately. The frontend clears count/continuation state during reload, displays the loaded count, refreshes after mutations and exposes read/unread controls with busy/error feedback. The bulk button sends only displayed unread IDs. Navigation/filter changes are disabled while a mutation is in flight; account guards ignore stale mutation responses.

Tests cover strict bounds, case-insensitive duplicate detection, overlapping retries, timestamp preservation, all-or-nothing mixed ownership/missing-ID failures, new arrivals, full-account counts, unread-filter behavior and suspended-account denial. Browser/keyboard/accessibility, real-time badges, bulk unread selections, notification retention and external delivery remain open. This is read-state management, not evidence that a linked booking/refund/support action completed.
