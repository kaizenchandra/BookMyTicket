# ADR 107: Versioned holiday definitions, pricing previews and allotment planning

Packages owns marketing/content definitions, itinerary and policy versions, commercial configuration, approval state, create replay and immutable history. Inventory owns departure-level planning caps via its public PackageAllotments contract. No Packages adapter reads Inventory's private tables. Supplier component reservations, failure compensation and fulfillment confirmation remain blocked by missing authorized supplier contracts/adapters; every public/preview response is bookable=false.

Definitions contain destinations, consecutive itinerary days, inclusive travel date ranges, media references/alt text, inclusions/exclusions, occupancy/adult/child limits, child-age/cancellation policy, mandatory components and optional add-ons. Components identify a supplier reference and adult/child/fixed group costs in INR paise. Component/add-on identities and departure starts are unique. Travel ranges must match itinerary day count. Drafts may be incomplete; submit/approve requires completeness and at least one non-past departure by database IST date.

Workflow: draft → submit → pending_review → approve → published. Reject returns to draft; unpublish returns published to draft. Pending review cannot be edited. Editing published content withdraws it to draft, with explicit confirmation. Version checks and row locks serialize writes; every definition/decision snapshot and audit commit atomically. Create keys are actor-scoped and fingerprinted, with stable code uniqueness preventing duplicate creation under new keys. Immutable history is paginated and includes supplier-allotment before/after snapshots.

Pricing preview validates departure, party limits, child ages and selected add-on identities. Component sum is adult count × adult cost + child count × child cost + fixed group costs. A basis-point markup applies to the summed component cost, rounded half up to paise, then the package fee and selected per-person/per-booking add-ons are added. All arithmetic uses bigint/decimal strings. This is configured commercial arithmetic, not a supplier quote, tax calculation or reservation. Caller values never override stored costs.

Planning limits use passenger-entitlement units, not rooms, vehicle seats or independently reserved supplier allocations. Each date records a package cap plus one cap for every current component. The minimum is reported as planningLimit only when the plan matches the current definition version; changed content or publication versions require reconfirmation. A party exceeding the plan reports withinPlanningLimit=false, while actual availability remains unknown. No capacity is consumed, held, sold or promised by this workflow. Connecting real supplier inventories must establish capacity conversion, authoritative allocation ownership and booking state semantics first.

packages.read/current MFA controls admin visibility, packages.manage definition/allotment/submit writes, and packages.review approval/rejection/unpublish. No permissions are automatically granted. Public content selects published records only and omits supplier references, component costs, markups, fixed fees and add-on prices. Public listings are explicitly informational. Allotment changes use independent versions and commit in the same local transaction as history/audit; failed audit rolls back Inventory and Packages writes together.

Remaining FR-11 work: authoritative availability and booking eligibility, supplier adapters, durable multi-component reservation orchestration, retries/unknown outcomes, compensation/cancellation/refund recovery, and component fulfillment/confirmation tracking. These need real supplier contracts, commercial/payment sequencing and authorized sandbox verification. No mock confirmations or successful compensation are shown. Browser acceptance and production-scale load testing remain outstanding.
