# ADR 050: Provider draft corrections and resubmission

FE:PRV-03/05/06 and BE:PRV-02 require resumable onboarding and corrections. The partner page now shows latest review feedback and an owner-only name editor for draft/changes_requested organizations, followed by an explicit submit/resubmit action. Organization kind remains unchanged; this does not implement contact, document, business or payout editing.

PUT /api/v1/organizations/:id/draft accepts a trimmed 2–150 character name and expectedVersion. The Providers application port delegates to its adapter, which locks the organization before checking/locking the current owner membership, matching staff-management lock order. Domain policy allows only draft/changes_requested states. Updates increment version; identical immediate retries preserve it. Stale changed requests return VERSION_CONFLICT; noneditable states return ORGANIZATION_NOT_EDITABLE. Existing database change triggers retain state/version audit evidence without copying the name into audit metadata.

Submission now uses the same owner locks and version policy. An identical retry for submitted at version+1 returns the recorded submission; later review/edit transitions do not replay it. Unauthorized submission now returns FORBIDDEN (403), replacing the previous generic CONFLICT. Kind/state cannot be injected into draft edits. Review feedback remains available as latest feedback after resubmission; it is not a claim that another review has completed.

Frontend drafts remain in memory across list refreshes. Dirty cards keep their reviewed version rather than silently adopting another edit. Save failures preserve inputs; an explicit discard/reload action recovers conflicts. Submission is disabled until local name edits are saved. Beforeunload warns for dirty drafts. API write responses do not grant frontend roles; backend permissions remain authoritative. Initial loading and refresh errors do not discard existing organization cards.

Tests exercise creation, owner edit/retry, submission retries, reviewer-requested corrections, racing edits, owner-role revocation, resubmission, approval lockout and rendered owner-only controls/escaped feedback. A synthetic reviewer fixture uses the existing platform moderation scope. No migration is required. Browser unsaved-change/multi-organization/accessibility acceptance, complete onboarding fields/documents/payout workflows and pagination remain open.
