# ADR 052: Durable provider review decisions

BE:PRV-06 requires recorded reviewer decisions and reasons. Migration 049 adds Providers-owned review_decisions with organization, input/resulting versions, reviewer ID, organization name at decision time, decision, reason and database timestamp. The organization/version key and version relationship provide business uniqueness. A database trigger prohibits mutation/deletion of decision records. Existing historical reasons are not backfilled because reviewer/version evidence is unavailable; latest legacy feedback remains on the organization.

The existing review transaction locks the organization, checks for a recorded decision for the submitted input version, and otherwise applies the transition and inserts its history atomically. A history-write failure rolls back the organization update and its existing audit trigger. Identical retries by the same reviewer return the original result; different reviewer/decision/reason requests for that input version return REVIEW_CONFLICT. Current route authentication, moderation permission and MFA still apply to retries. Replaying an earlier decision never writes current state, including after resubmission or rejection. New approvals retain completeness and self-review checks.

Owner GET /api/v1/organizations/:id/reviews returns decision versions, reason and time without reviewer identity. Reviewer GET /api/v1/admin/providers/:id/reviews also returns reviewer UUID. Moderator permission and active account are rechecked through Identity's StaffAuthorization contract within the history transaction; owner membership is similarly checked under lock. Access audits contain audience/count/page metadata, not decision text. Audit failure prevents disclosure. Pages contain at most 20 records, newest version first; beforeVersion is an ordering boundary, not authorization.

The owner partner page provides history, and administrators can inspect current or past applications at /admin/provider-history?organizationId=UUID after they leave the active queue. Both views distinguish historical decisions from current application state and explain the absence of legacy records. The existing rejected decision is now exposed next to approve/request-changes in the protected reviewer form. Supplied reasons render as escaped text. The missing parent wiring for unsaved private-form submission blocking was corrected and a disabled-control render assertion added.

Tests cover concurrent retries, conflicting payloads, old replay after later state changes, 22-record pagination, owner/reviewer identity projection, permission revocation, immutable records, transactional write rollback and audited-read failure. Browser/history/reviewer/rejection/keyboard/accessibility acceptance and approved history-retention policy remain open. Full historical private application snapshots and under-review assignment/lifecycle are separate remaining work.
