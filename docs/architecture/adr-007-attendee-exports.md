# ADR 007 — Bounded, encrypted attendee export jobs

Reporting owns durable export jobs and encrypted CSV artifacts. Bookings provides confirmed registrations through an in-process contract; Events provides immutable field definitions; Inventory provides occurrence scope; Identity and Providers authorize current actor status and organization ownership. Composition connects ports without cross-module repository access.

Development policy: only organization owners may export; an export selects one occurrence and one historical form version, explicit fields, and a purpose. Customer contacts, ticket tokens and unselected answers are never included. Fields shared across form versions are not assumed equivalent. Exports include confirmed orders only, with order reference and attendee ordinal. Request fingerprints and actor-scoped keys make retries safe. At most five queued jobs per actor, 1,000 registrations and 2 MiB CSV per job; larger exports fail explicitly rather than truncate.

Request, execution, status and download recheck active identity, organization ownership and provider approval. Authorization rows are held with shared locks during execution/download, so revocation is serialized with data release. Downloads are requester-only, authenticated and no-store; there are no public bearer URLs. CSV fields are quoted and formula/control prefixes neutralized. Artifacts use a dedicated AES-256-GCM key with job/actor associated data, never plaintext persistence. Download authorization cannot retract bytes already delivered.

The worker locks one queued job using SKIP LOCKED and performs bounded database-only work in a single transaction; no external calls or long-lived detached workers. A crash rolls back the claim and output. A savepoint isolates a failed attempt, retaining a safe error code and bounded retries/backoff. After three failures the job requires a new explicit request; automatic infinite replay is forbidden. Forbidden requests become terminal. Expiry uses database time, clears ciphertext in bounded worker batches and rejects downloads even if cleanup has not run. Lifetime is 24 hours from request, with snapshot freshness recorded at generation.

This deliberately avoids a lease for work that completes inside one database transaction. Streaming large exports, administrator replay, per-field sensitivity classes, managed key rotation and configurable production retention remain separate requirements. Owners-only permission and lifetime are development defaults, not approved production policies.

Acceptance: tenant/role/account revocation at queue execution and download, changed-key input, encrypted storage, selected-field minimization, CSV formula defense, expiry, retry recovery and concurrent workers. Browser acceptance is reported separately.

Requests and downloads require a recent MFA-verified HTTP session. Workers recheck the account/organization authorization independently of browser state. Worker queries have a 3-second lock timeout and 10-second statement timeout. PostgreSQL queue locking semantics were checked against the [official SELECT documentation](https://www.postgresql.org/docs/current/sql-select.html#SQL-FOR-UPDATE-SHARE).
