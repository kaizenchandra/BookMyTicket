# ADR 103: Hotel property content and publication

FR-06 is implemented as a Hotels module in the modular monolith. It owns hotel/homestay master content, stable property codes, coordinates, associated contracting-party name/reference, image URL/alt metadata, amenities, facilities, house rules, check-in/out times, cancellation policy text and immutable revisions. Associated supplier metadata is operator-entered; it does not verify supplier identity or activate an integration. External content synchronization (FR-BE-038) awaits an authorized supplier contract and credentials.

Identity owns hotels.read, hotels.manage and hotels.review platform grants; existing roles/accounts receive none automatically. Admin routes require current MFA. Application transactions recheck active platform permissions. Read access includes private contacts and revision snapshots; public publication projection explicitly removes contacts and supplier association. Public listing data is informational and always bookable=false; FR-07 inventory/rates and hotel booking are separate work.

Draft content may be incomplete but must satisfy structural limits and valid nonempty email/phone/time/image formats. Completeness checks require name, description >=40 characters, location/address/coordinates, contacts, supplier name/reference, images with alt metadata, amenities, house rules and policies before both submission and approval. Images are HTTPS references, not server downloads or managed uploads. Text renders as escaped React content, never HTML.

Lifecycle: draft → submit → pending_review → approve → published; reject returns pending_review to draft with a recorded reason. Published listings may suspend or delist; suspended listings may delist. Reopen returns suspended/delisted to draft. Editing a published record immediately returns it to draft, with an explicit UI confirmation, so unreviewed changes are never public. Pending-review records cannot be edited. Reviewers can review their own submissions; separation of duties is not imposed by this FRS.

Mutations lock the property, compare expectedVersion, increment the content/state version, append a full immutable revision and audit state/version metadata in one transaction. Policy history is preserved in those snapshots. Audit payloads exclude private property content. Database triggers prohibit revision updates/deletes. Create requests lock actor/key, compare fingerprints and retain original results; unique stable codes prevent duplicate properties after request replay retention. Audit failure rolls back both current and historical content.

City/kind/state/name and optional bounding-box filters run before 25-row timestamp/UUID keyset pagination. Coordinates have a published-row B-tree location index; this is a bounding-box search, not PostGIS distance ranking, geocoding or antimeridian-crossing search. Public requests always select published rows even when requesting another state. Publication uses authoritative live queries; no cache invalidation/outbox is required yet.

No room pricing, supplier booking, cancellation penalty calculation or live supplier synchronization is fabricated. Browser acceptance remains separate from successful database/HTTP, build and container verification.
