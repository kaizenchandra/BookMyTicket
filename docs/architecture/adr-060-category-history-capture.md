# ADR 060: Retaining additional category content

FE:CAT-06 and BE:CAT-07 require history to retain supplied category content. Existing typed category adapters persisted complete details in their own modules, but omitted some customer-facing content from Catalog metadata and therefore from future Catalog revisions. Cinema now supplies crew; Events supplies organizer, inclusions, exclusions and entryInstructions; Sports supplies season, homeTeam, awayTeam and hospitality through the CategoryDrafts public contract's retainedMetadata projection. Catalog merges this into listing metadata in the existing local transaction. Category rows and listing metadata continue to commit together.

These fields are supplied customer-facing content already returned by category detail APIs. They may also be present in published listing metadata; they are not private payout/contact data. History's per-kind allowlist and frontend labels now include them. Unknown/internal fields remain omitted. No cross-module private table reads or inferred historical values are introduced.

Idempotency compatibility matters when expanding derived projections. Category owners already supply requestFingerprint, a hash of the complete validated input including these fields. For those inputs, Catalog excludes the new retainedMetadata projection from the legacy command fingerprint envelope, preserving pre-upgrade command identity. The original input hash still rejects changed crew/exclusions/hospitality under the same key. Inputs without a requestFingerprint retain full-input hashing, including retainedMetadata. Callers must ensure their canonical fingerprint covers every supplied field.

Replays return the existing listing and never update its metadata or create new history. A future explicit save writes the additional values to the current listing; subsequent edits/submissions/reviews preserve that row in the existing immutable revision mechanism. Older revisions remain unchanged and show missing fields as Not recorded. This increment does not reconstruct missing old values or add poster/media history.

Existing end-to-end cinema, sports and event scenarios now assert compatibility against the exact pre-upgrade fingerprint formula, changed-payload conflicts, replay non-mutation, saved original category values and later comparison changes, then continue through publication, booking and cancellation. Tests also verify legacy-null values, expanded labels and escaped content. Browser/history/accessibility and approved retention/restore policy remain open.
