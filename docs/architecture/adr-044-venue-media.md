# ADR 044: Venue photo and map references

FE:VEN-04 requires supplied venue photographs/maps. Venue-owned ordered media references provide this without introducing a new storage service. Migration 044 adds an empty JSONB array and independent media version to existing venues. Each of at most eight entries has an HTTPS URL, photo/map kind, nonempty alternative text, caption and attribution. Domain policy rejects credentials, fragments, whitespace/backslashes and canonical duplicate URLs. Transport schemas bound URL/text lengths and reject unknown fields. No arbitrary HTML is accepted.

POST /api/v1/organizations/:id/venues/:venueId/media replaces the ordered array under expectedVersion. The application validates media policy and the adapter rechecks writable tenant membership in a transaction, locks the tenant-owned venue, enforces the version and atomically audits venue.media_updated. The audit includes organization/version/count, not URLs or descriptions. Failure to audit rolls back the change. Stale saves return 409; empty arrays remove all references. Media revisions do not modify occurrence/booking snapshots.

The provider editor supports add, preview, metadata editing, move up/down and remove. Public media passes the existing approved-provider/published-listing venue gates. The customer gallery renders escaped descriptions/credits without requesting images; a per-image button opts into the external request, with no-referrer policy and a failed-image fallback. Images render as img elements, never embedded documents. Third-party hosts receive the viewer network address when loaded. The server never fetches supplied URLs, resolves their hostnames or claims they contain valid/licensed images. It does not proxy, scan, host or crop media. Hosts can change content or redirect; opt-in rendering and schema validation are not a media moderation system.

Tests cover strict URL/metadata bounds, tenant/viewer denial, concurrent saves, ordering, publication withdrawal, removal and audit rollback. A React server-render test verifies initial no-image/no-preload behavior, escaped captions and available descriptions. It does not establish browser image-loading or visual/accessibility acceptance. Upload/crop, controlled storage, media moderation, asset availability and full browser acceptance remain open. This is a venue-only subset, not complete catalog media management.
