# ADR 008 — Authenticated ticket wallet, portable documents and calendar

Bookings orchestrates owner-only ticket retrieval under a local unit of work. It holds the order, reads current occurrence metadata through Inventory and reads owned entitlements through Ticketing. Lock order is order → occurrences (sorted) → tickets, compatible with confirmation and occurrence → ticket admission. Issuance and document rendering remain separate: rendering retries never create or rotate tickets.

Only confirmed bookings expose credentials. Per-ticket status combines stored revocation/replacement, current occurrence cancellation/expiry and remaining admission count; non-admissible tickets carry no QR credential. Future valid tickets may display their QR before the admission window, with the actual opening time and a server-verification notice. The existing development admission policy (one hour before start through end) is explicitly labeled; configurable windows remain outstanding. Pending issuance is reported when confirmed quantity exceeds issued tickets, not presented as confirmed delivery.

QR rendering uses pinned node-qrcode locally; no third-party service receives tokens. Authenticated responses and downloads are no-store. Ticket IDs are readable; tokens never enter public URLs, analytics, calendar data or logs. A printable HTML attachment uses escaped metadata, embedded QR images, no scripts/external resources and restrictive CSP. It is an offline display snapshot, not an offline admission verifier. User-controlled download is intentional; no automatic browser persistence is added.

Calendar export is independent of ticket decryption/rendering. RFC 5545 UTC timestamps preserve event instants; descriptions retain the venue-local IANA zone. Text is escaped, CRLF-normalized and folded by UTF-8 octets. UIDs identify occurrences, not customers or ticket credentials. Cancelled occurrences produce cancelled calendar entries; pending bookings cannot export calendar events. Static imports do not automatically receive schedule changes.

This slice does not implement transfers, cancellation/refund orchestration, delivery/resend, camera scanning, configurable re-entry, PDF generation, offline duplicate prevention or live payment verification. Browser/print/visual acceptance is reported separately. Sources checked: https://github.com/soldair/node-qrcode and https://www.rfc-editor.org/rfc/rfc5545.
