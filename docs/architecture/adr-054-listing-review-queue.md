# ADR 054: Listing review queue pagination

FE:ADM-UI-05, FE:INT-09 and BE:API-05 require accessible listing reviews with bounded, stable pagination. The old aggregate review API returned only the first 100 submitted listings. GET /api/v1/admin/listings now exposes pages of 20 with optional movie/event/sports filters and an exclusive creation-time/UUID continuation boundary. The Catalog application port owns this query. Every request authenticates the account and checks current moderation permission and existing MFA policy.

Queries select explicit review metadata rather than all listing columns. Database timestamps retain six fractional digits so continuation does not lose PostgreSQL microseconds through JavaScript Date conversion. Both cursor fields are required together, unknown filters are rejected, and an empty kind is accepted for native all-types forms. Migration 051 adds partial indexes for submitted-state ordering with and without kind filters. The endpoint reads 21 rows to detect the next page.

The dedicated /admin/listings page provides filters, first/next links, loading/error/empty states, current-page refresh and inline decision/reason forms. Form controls disable during saving and reasons remain available on failure. Submitted review versions continue to protect against stale decisions. Successful decisions reload the current queue. Unknown outcomes require refreshing to observe current state: listing decision replay remains the existing version-conflict behavior, unlike provider decision replay. No automatic retry claims are made.

/admin now links to listing reviews and no longer calls the aggregate endpoint. The legacy /api/v1/admin/reviews endpoint remains backward compatible with its capped arrays, and should not be used as a complete queue API. Provider and listing page/filter URLs are independent. Session changes clear listing data; the route is keyed to the active account. User text is rendered escaped.

This is a live queue ordered by original listing creation time, not a frozen snapshot or submission-time FIFO. Reviewed listings disappear; earlier listings resubmitted behind a continuation boundary require a return to the first page. Tests cover 105 equal-time listings, boundary-row removal, validation, filters, empty pages, authentication/authorization/revocation, response schema, actual decision removal and stale publication protection. Server-render tests cover escaped content, decision controls and URL boundaries. Browser/navigation/scroll/accessibility, unsaved-reason navigation protection and measured load performance remain open.
