# ADR 058: Saved revision comparison

FE:CAT-06, FE:CAT-08 and BE:CAT-07 benefit from structured review of retained revisions. GET /api/v1/listings/:id/revisions/compare and its /api/v1/admin/listings counterpart accept distinct fromId/toId decimal bigint strings. Both records must belong to the requested listing. Missing or foreign records produce the same not-found error; a cursor is never authorization. Current membership or moderation permission/MFA is required, using the established public contracts and shared-lock transaction pattern.

Catalog's pure domain comparison policy compares exactly title, description, city, kind and state, in stable field order. It returns only changed fields, preserving null versus empty strings and exact text. The adapters project the same safe core fields as revision history and never expose metadata, URLs, actor IDs, reasons or full stored snapshots through comparison. The result identifies both input revision IDs/versions; direction follows the user's From/To selection rather than silently sorting IDs. Identical content produces an empty changes array.

Access auditing occurs in the transaction before returning. Audit metadata contains revision references and changed field names, not content. Failed audits withhold comparison data. Revisions remain immutable under migration 053; no new migration is required. The existing listing/ID index supports the two-record query.

Revision cards now offer Use as From revision and Use as To revision. Selections persist across history page changes and can be entered manually; session changes clear them. Comparison is explicit, and changed selection cancels stale-result presentation. The table displays changed values side by side, with null and empty text separately labeled. It compares two pre-change snapshots, not the current draft, not a complete change log, and does not restore or publish anything.

Integration tests cover direction, exact IDs above JavaScript safe integers, response schema, required/distinct/bounded references, member/moderator access, cross-listing rejection even within the same organization, revocation and audit failure. Pure comparison/server-render tests cover unchanged data, null versus empty, stable fields, HTML escaping and table semantics. Browser/paging/keyboard/accessibility acceptance remains open, along with category-specific history and restore policy.
