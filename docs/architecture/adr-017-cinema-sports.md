# ADR 017 — Cinema and sports modules with explicit local demo catalog

Cinema and Sports now own typed movie and fixture details in their own schemas. Catalog owns publication/revisions/search metadata. A public CategoryDrafts port creates/updates catalog drafts in the same transaction as category details; projection metadata is updated atomically. Scoped create/update keys include a digest of the full category request. Replaying an old request returns its listing without overwriting newer category details. Generic catalog edits reject managed category drafts, which must use their category editor.

Movies include duration, release date, certification, genre, language, format, cast and crew. Fixtures include sport, competition, season, opposing participants, entry instructions and hospitality description; identical participants are rejected. Provider editors create/edit drafts and use existing moderation to publish. Published detail APIs read category-owned data after a locked catalog publication check. Venue plans, screen overlap/turnaround checks, occurrences, pricing, reservations and all allocation remain with their existing authoritative modules.

Customer details render typed information and actual venue-local dates. Session selection filters by date/venue, shows real current inventory counts and prices, and disables unavailable sessions. This is a read model; reservation is still authoritative. Existing assigned-seat and general-admission UI displays plan sections, gates and accessibility information. Current integration tests traverse provider HTTP creation/review, venue/plan/schedule, policy approval, customer reservation/quote/order, free confirmation, QR wallet and full free cancellation for both categories.

The latest user explicitly requested mock, realistic-looking cinema and sports data. This supersedes the earlier no-mock-catalog constraint only for that local demo scope. Seven fictional listings, original repository-owned SVG posters, two demo organizations and a labeled demo operator account are created by an opt-in local seed script. Four movies and three sports fixtures span Bengaluru, Mumbai and Chennai. Each has a free demo session and a priced demonstration session. Names, descriptions, cards and posters identify fiction; venues are not real travel destinations. No customer bookings, reviews, revenue, captures or analytics are seeded.

Demo occurrences have a durable is_demo flag. It is copied to reservation/quote snapshots, and PaymentOrders rejects real payment preparation for demo inventory independently of payment-provider configuration. The ₹0 demo path uses real inventory, order, ticket, cancellation and outbox components, without manufacturing a payment. Priced demo sessions demonstrate pricing but cannot collect money. This is not Razorpay Test Mode verification or live merchant verification.

The script requires NODE_ENV=development, ALLOW_DEMO_SEED=1, a recognized local database name and local host. Repeating the successful seed reuses listings/sessions and never resets sold stock or existing bookings. Repeating is not a general partial-import recovery system; interrupted provisioning may require inspection. Future dates are set on initial creation, not extended on every run. Do not roll back to an artifact without demo-payment protection while these records exist. No production seeding or destructive cleanup is authorized by this workflow.

Migration 022 adds cinema/sports data, category command records and the demo occurrence flag. Shared catalog writes remain behind contracts; no category module maintains availability counters. Keep typed tables and command records when rolling back to a compatible artifact.

Limits remain explicit: multi-language per-show variants, complete release/publication rules, bulk schedule imports, concessions, sports season/multi-fixture passes, complex hospitality fulfillment, sports credential redemption, disruptions and paid refund workflows are incomplete. Browser visual, keyboard, viewport, accessibility and physical scanner acceptance remain blocked/unverified. No full detailed CIN/SPT requirement completion is claimed.
