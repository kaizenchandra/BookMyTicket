# ADR 051: Private provider business and contact drafts

FE:PRV-02/03/06 and BE:PRV-02/03 require business/contact onboarding beyond the organization name. Migration 048 adds Providers-owned onboarding_details, separate from the organizations table. It stores business name/address, contact person/email and optional international phone. These supplied contacts are not verified identity credentials, public venue contacts or payout destinations. No outbound message is sent.

The initial common workflow for cinema/event/sports permits incomplete saved drafts but requires nonempty legal business name, business address, contact name and email before submission or approval. API schemas bound strings and validate supplied email/phone syntax. Completeness checks run under the organization row lock shared by draft writes/reviews. This changes submission behavior: older incomplete drafts and submitted applications need owner corrections before submission/approval. Previously approved organizations are not automatically suspended or altered. Document and payout verification are separate remaining requirements; populated fields do not establish business eligibility.

Owner GET/PUT /api/v1/organizations/:id/onboarding require current owner membership. GET /api/v1/admin/providers/:id/onboarding requires the existing platform moderation permission/MFA policy. Ordinary organization lists and review queues contain no private field values. The private view is loaded explicitly; reviewer approval controls use the version returned by that view. Organization kind remains immutable in this workflow.

Private saves lock organization then membership, matching existing staff/draft lock order, enforce editability and expectedVersion, update the private row, increment organization version and audit atomically. Identical immediate retries do not duplicate writes. Read audits commit before private data is returned; audit failures withhold reads or roll back writes. Audit payloads include version, not supplied field contents. Routes retain no-store behavior. Details are not field-encrypted by this increment; deployment storage protection and approved retention remain part of broader release security/privacy work.

The owner form supports partial saves, explicit reload/discard, beforeunload warnings, read-only submitted/approved views and preserved failed-save drafts. Unsaved private edits block the adjacent submission action. Organization list refresh does not replace these drafts. Reviewers can inspect the fields and approve or request corrections; stale decisions are rejected by organization version.

Tests cover incomplete-submission rejection, strict field validation, concurrent saves/retries, owner/editor/reviewer boundaries, list omission, audited read/write rollback, submission freeze and approval. Existing publication fixtures now provide required synthetic onboarding fields. Browser/multi-form/account-switch/accessibility acceptance, supporting documents, payout controls, field/history retention, full legal/commercial verification and broader provider lifecycle remain open.
