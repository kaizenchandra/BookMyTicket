# ADR 055: Durable listing review decisions and replay

BE:CAT-07, BE:API-03 and FE:ADM-UI-05 require review integrity and recoverable operations. Listing reviews previously omitted reviewer identity from revisions and returned a stale-version conflict after a committed decision's response was lost. Migration 052 adds Catalog-owned immutable review_decisions keyed by listing and input version, storing reviewer, decision, reason, resulting version, original result and database time. Existing decisions are not reconstructed without reliable reviewer evidence.

The review transaction first checks active-account/moderation permission through Identity's StaffAuthorization contract, locks the listing, and looks for an existing decision at the input version. The same reviewer, decision and normalized reason receive the original serialized result. Different actor/decision/reason conflicts. Replay returns historical data without executing any transition or provider approval checks; it cannot republish a subsequently suspended listing. HTTP authentication and fresh-MFA policy still apply before the transaction, and current permission is required even for replay.

New transitions retain submitted-version and approved-provider checks. The existing revision now records the reviewer actor. Revision, state update and immutable result commit atomically; a failed decision insert rolls back all three. Requests validate bounded versions and trimmed nonblank reasons. The business key remains durable rather than depending on a temporary idempotency-key TTL. Legacy versions without durable records retain existing stale-version conflict behavior.

The listing form preserves a copy of the attempted payload and offers Retry original decision after failure. Editing visible fields does not change the stored retry payload. An explicit new form submission creates a new attempt and may conflict if another decision already committed. Success refreshes actual queue state because a replay's returned result may be historical. Browser close loses this in-memory attempt; there is no claim of cross-session draft persistence. Unsaved navigation and browser/accessibility acceptance remain open.

The local demo publisher now passes a configured DEMO_REVIEWER_ID and uses the real authorization adapter. It requires an existing active moderator instead of bypassing review permissions. No moderator is granted or seed command run by this change. Existing published demo data is unaffected.

Integration tests cover concurrent identical decisions, changed reason/actor conflicts, blank reason rejection, reviewer attribution, failed-history-write rollback, replay after resubmission and suspension, immutability and permission revocation at both HTTP and adapter boundaries. Full decision-history UI, retention approval, broader listing lifecycle policies and browser acceptance remain open.
