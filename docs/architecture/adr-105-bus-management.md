# ADR 105: Bus reference catalogue and local incident administration

FR-08 depends on a bus supplier's live availability, fare, seat-hold, booking, ticket and asynchronous status contracts. No authorized supplier/API documentation/sandbox configuration was provided during this increment. The Bus module therefore implements real local catalogue administration without simulating supplier responses or exposing bookable seats. Availability, booked-seat counts and booking/ticket status return null with integration state not_configured. Live supplier workflows remain blocked.

The Buses module owns typed operator, route and service records with stable kind/code uniqueness, current version and immutable history. Operator profiles carry business contacts and supplier reference metadata, not secrets. Routes have ordered boarding/drop-off points, addresses and minute offsets from service departure. Services reference active local operators/routes, snapshot the accepted route, and contain timezone-qualified departure/arrival, amenities, seat layout/reference fares and cancellation-rule references. Route edits do not silently rewrite service snapshots; explicitly saving a service refreshes its snapshot.

Domain rules reject duplicate case-insensitive seat labels, overlapping deck/row/column cells, non-increasing stop groups, matching origin/destination, arrival before departure and drop-off offsets beyond service duration. Seat geometry is a reference grid (lower/upper deck, seater/sleeper); it is not a normalized representation of every supplier layout. Fare amounts use decimal INR paise strings. Cancellation text, free-cutoff hours and penalty basis points are references, not executable supplier cancellation/refund authority.

Services start planned, can become disrupted and resolve back to planned, or withdraw terminally. These are local incident states. Withdrawal does not cancel supplier reservations, move money or send communications. Withdrawn records cannot be edited/reopened; history is retained. Operator/route suspension prevents their selection for new/edited services but does not change existing service snapshots or claim external cancellations.

Identity owns buses.read and buses.manage grants; no account receives them automatically. Reads require buses.read and current MFA; all writes additionally require buses.manage inside the transaction. Each edit/disruption locks its record and checks expectedVersion. Service references are validated under parent share locks. Create requests serialize by actor/operation/key and reject changed fingerprints, while stable catalogue codes prevent duplicate creates under new keys. Current record, full before/after history and redacted audit commit together. History has immutable database triggers and cursor pagination. No adapter crosses private module SQL boundaries.

Directory filters are applied before 25-row timestamp/UUID keyset pagination. Service-only filters include operator, route and departure window. List cursors bind actor, kind and filters. Business contacts and full history are visible only to authorized bus administrators; there is no public bus API in this increment.

Before claiming FR-08 completion: choose the authorized supplier, verify its official contract, implement its authenticated adapter and normalized routes/fares/layouts, define supplier seat-hold support, build booking/payment/supplier state separation with durable reconciliation of uncertain outcomes, synchronize disruptions/departures/cancellations, and prove sandbox ticket confirmation and retry semantics. A local catalogue or manual incident must never substitute for those guarantees. Browser acceptance and production-scale load tests remain outstanding.
